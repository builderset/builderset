_This page describes Builderset 0.5.1._

Every builder keeps its document the same way, so one design serves all five: a row
per document with its **live** version, the **draft** since, and a `saved_at` that
catches two people saving at once. Around it, every row records **who made it,
who last changed it and who deleted it, and when**; deleting is a **soft delete**
that can be undone; and two kinds of history sit beside each document — its
**revisions** (what it said) and its **activity** (what happened to it).

The framework pages — [SQL](/docs/guides/backend/sql),
[Supabase](/docs/guides/backend/supabase), [Django](/docs/guides/backend/django),
[FastAPI](/docs/guides/backend/fastapi), [Node.js](/docs/guides/backend/express),
[Laravel](/docs/guides/backend/laravel), [Spring Boot](/docs/guides/backend/spring-boot)
and [ASP.NET Core](/docs/guides/backend/aspnet-core) — build exactly these tables
and routes.

## The tables at a glance

| Group           | Tables                                                            | What they hold                                                       |
| --------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------- |
| Email templates | `email_template`, `email_template_revision`                       | Designs for each email your app sends, and their versions            |
| Articles        | `article`, `article_revision`                                     | Pages of your site's blog or help centre, per language               |
| Forms           | `form`, `form_revision`, `form_response`                          | Forms, their versions, and what visitors sent                        |
| Cards           | `card_design`, `card_design_revision`, `card_issue`               | Card designs, their versions, and each card made out to a member     |
| Popups          | `popup`, `popup_revision`, `popup_submission`, `popup_daily_stat` | Popups, their versions, what visitors sent, and how each did per day |
| Library         | `saved_section`, `media`                                          | Pieces of documents saved to reuse, and every uploaded file          |
| Activity        | `activity`                                                        | Who did what to which row, and when; never edited                    |

## What every row has

Every table carries the same audit columns. Your server writes them; it never takes
them from the request:

| Field        | Type                | What it is                                                               |
| ------------ | ------------------- | ------------------------------------------------------------------------ |
| `id`         | bigint              | The row, for joins. Never leaves the server                              |
| `uuid`       | UUID, unique        | The public id: the only one in URLs and answers, where it is called `id` |
| `created_at` | timestamp           | When the row was made                                                    |
| `created_by` | your user, nullable | Who made it. Null for a visitor's form response, or a row a job made     |
| `updated_at` | timestamp           | When anything in the row last changed — a trigger or the ORM keeps it    |
| `updated_by` | your user, nullable | Who made that change                                                     |
| `deleted_at` | timestamp, nullable | When it was deleted. Null means live; every list filters on it           |
| `deleted_by` | your user, nullable | Who deleted it                                                           |

The user columns point at your users table with **on delete set null**: removing a
person keeps everything they made, without their name on it. Unique rules — an
article's address, a form's slug, the one active design per email type — hold only
among live rows, so deleting a row frees its address.

<Callout title="Two clocks">
  `updated_at` changes on any write to the row: a status, a rename, a triage. `saved_at` changes
  only when the **document** is written, to the millisecond, and is what the editor sends back to
  detect a stale save. Keep both.
</Callout>

## The documents

Each document table adds these to the audit columns:

| Field            | Type                | What it is                                                                               |
| ---------------- | ------------------- | ---------------------------------------------------------------------------------------- |
| `document`       | JSON                | The live document: what readers get, what is sent, what the form shows. Checked strictly |
| `draft_document` | JSON, nullable      | Work in progress since the last publish. May be unfinished, never unsafe                 |
| `saved_at`       | timestamp (ms)      | Changes on every document write. A save that brings an older one is a stale copy: `409`  |
| `status`         | text                | Where it is: `draft`, `published`, and per builder `scheduled`, `archived`, `closed`     |
| `version`        | integer             | Counts publishes; a revision and a form response record the one they belong to           |
| `published_at`   | timestamp, nullable | The last publish (an article keeps its first, for its list)                              |
| `published_by`   | your user, nullable | Who published it                                                                         |

A JSON column holds the document as it is: `jsonb` in PostgreSQL, `JSON` in MySQL,
a text column elsewhere. The site never reads inside it for lists or search — those
read the columns below, which are copies written in the same transaction.

## History

Two tables answer two questions. **Revisions** answer "what did it say?": a whole
document, to look at or restore. **Activity** answers "what happened?": one line per
action, with who and when.

<Tabs label="History">
<Tab title="Revisions">

One table per builder — `email_template_revision`, `article_revision`,
`form_revision`, `card_design_revision`, `popup_revision` — so each has a real foreign key, deleted with its document:

| Field                      | Type                          | What it is                                                     |
| -------------------------- | ----------------------------- | -------------------------------------------------------------- |
| `uuid`                     | UUID                          | Its public id                                                  |
| the document               | the email, article or form    | Whose version it is                                            |
| `kind`                     | `autosave`·`manual`·`publish` | Why it was written                                             |
| `label`                    | text, nullable                | A name someone gave it: "Before the legal review"              |
| `version`                  | integer                       | The document's `version` then; a response finds its form by it |
| `document`                 | JSON                          | The whole document                                             |
| `created_at`, `created_by` | timestamp, your user          | When, and whose work it is                                     |

A revision is written once and never changed, so it has no `updated_*` or
`deleted_*`; restoring one writes a new one. Record one on every manual save and
every publish; keep few autosaves (the last twenty, or one every ten minutes) or the
table grows by a whole document every few seconds of typing.

</Tab>
<Tab title="Activity">

One table for every kind of row, written in the same transaction as what it records:

| Field                        | Type                | What it is                                                                                                                                                           |
| ---------------------------- | ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `subject_type`, `subject_id` | text, bigint        | Which row: `article` 7, `popup` 3, `card_issue` 41. No foreign key — the log outlives what it describes                                                              |
| `action`                     | text                | `created`, `saved`, `renamed`, `published`, `scheduled`, `unpublished`, `closed`, `paused`, `issued`, `revoked`, `reverted`, `status_changed`, `deleted`, `restored` |
| `from_status`, `to_status`   | text, nullable      | For a change of status: `draft` → `published`                                                                                                                        |
| `details`                    | JSON                | What else matters: the old slug, the revision restored                                                                                                               |
| `actor`                      | your user, nullable | Who did it. Null for a job (a scheduled publish) or a visitor                                                                                                        |
| `created_at`                 | timestamp           | When                                                                                                                                                                 |

Autosaves are not logged — they are revisions at most. The log is only ever
appended to: give your app's database role no `update` or `delete` on it.

</Tab>
</Tabs>

## The routes

`{kind}` is `emails`, `articles`, `forms`, `cards` or `popups`, and `:id` is the row's `uuid`. The
routes marked **editor** are what [`createRestHost`](/docs/guides/host) calls; the
others are for your own screens.

<Tab title="Documents">

## What each write does

Every write that changes a row does the same four things, in one transaction:

1. **Checks** the document, when there is one (below).
2. **Writes** the row, with `updated_by` — and `created_by`, `published_by` or
   `deleted_by` — set to the signed-in user.
3. **Records a revision** on a manual save or a publish.
4. **Appends an activity** row for anything but an autosave.

| Write                         | Node                                                      | Python                               |
| ----------------------------- | --------------------------------------------------------- | ------------------------------------ |
| An email's draft or publish   | `parseEmail`, then `checkEmail(document, registry, type)` | `check_email(document, spec)`        |
| An article's draft or publish | `parseArticle`, then `checkArticle(document, registry)`   | `check_article(document)`            |
| A form's draft or publish     | `parseForm`, then `checkForm(document, registry)`         | `check_form(document)`               |
| A form's response             | `validateAnswers(form, answers)`                          | `validate_answers(form, answers)`    |
| A card design                 | `parseCard`, then `checkCard(document, registry)`         | `check_card(document)`               |
| A popup                       | `parsePopup`, then `checkPopup(document, registry)`       | `check_popup(document)`              |
| A popup's submission          | `validateSubmission(popup, values)`                       | `validate_submission(popup, values)` |

A draft is refused only for what `isDraftBlocking` names — an unsafe link, a broken
tree — and publishing for any error. A form response is checked against the
**published** document, never the draft, and only `values` is stored: answers to
questions the visitor was not shown are dropped, and anything the form does not ask
never reaches the table.
