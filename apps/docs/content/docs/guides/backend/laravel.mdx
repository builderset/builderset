_This page describes Builderset 0.4.0._

At the end a Laravel app stores email templates, articles, forms, card designs and
popups with everything the [data model](/docs/guides/backend/data-model) asks of a real
app: who made, changed, published and deleted each row and when, a trash to restore
from, a revision on every manual save and publish, and an activity line for everything
that happens. It refuses an unsafe or stale save with the editor's own issue codes,
takes form responses and popup submissions checked exactly as the browser checked them,
and issues cards to members.

Tested with Laravel 12.73 on PHP 8.3.37, opis/json-schema 2.6.2, PostgreSQL 18, and
the checker on Node 26. About 25 minutes to read.

There is no Builderset package for PHP, so every document is checked in two layers. Its
**structure** is checked in-process, against the kit's JSON Schema, with
`opis/json-schema`. The **kits' own rules** — an unsafe link, a variable the email type
does not have, a form's answers — run in the
[Builderset checker](/docs/guides/backend/checker), a small Node service beside the
app that runs the same functions the editor runs. When the checker cannot be reached,
the app answers `503` and stores nothing.

The files below go into a new Laravel app, at the paths their titles give:

```txt title="my-app/"
config/builderset.php      the checker's address, your email types
bootstrap/app.php          the API routes, and the one place errors become answers
database/migrations/       one migration per group of tables
app/Database/              the audit columns, written once for the migrations
app/Enums/                 statuses, revision kinds, actions, the five kinds
app/Models/                one model per table, on a shared Audited trait
app/Builderset/            the JSON Schemas, the checker's client, the two together
app/Services/Documents.php what every write to a document does
app/Http/                  the stand-in sign-in, form requests, resources, controllers
app/Policies/              who may publish
routes/api.php             the routes, grouped per concern
```

### One set of routes for five builders

What the shared routes ask of a builder, by the word in its URL:

<include cwd lang="php" meta='title="app/Enums/DocumentKind.php"'>
  ./snippets/backends/laravel/app/Enums/DocumentKind.php
</include>

`DocumentController` is written once; Laravel binds `{kind}` to the enum, and an unknown
one is a `404`. Each method reads the request and answers; the work is in `Documents`,
which does what every write does in one transaction: write the row with who did it,
keep a revision on a manual save or a publish, append an activity line. The checker is
asked before the transaction starts, so no row stays locked while it answers. Lists
answer `{ items, total }`, with `?status=`, `?q=`, `?limit=`, `?offset=`, and
`?deleted=true` for the trash.
