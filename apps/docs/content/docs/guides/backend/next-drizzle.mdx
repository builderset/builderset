---

At the end your Next.js app stores email templates in Postgres, refuses an unsafe or
stale save, and renders a published template to send. Every file below is from
[`examples/backends/next-drizzle`](https://github.com/builderset/builderset/tree/development/examples/backends/next-drizzle),
whose tests run every route against a real Postgres on each change. The same routes
are in [Prisma](/docs/guides/backend/next-prisma) and in
[FastAPI](/docs/guides/backend/fastapi-sqlalchemy).

_This page describes Builderset 0.4.0._

Every document is checked before it is stored, with the editor's own rules: a draft

### Saving a draft

The editor sends back the `saved_at` it last saw. A different one on the row means
someone else saved in between: `409`, and the editor offers to reload or keep its
own. The update is conditional, so two saves at the same instant cannot both win:

## The tests

Create, save, a stale save (`409`), publish, send, every invalid document of the
email kit's fixtures (`422` with its code), an unfinished draft that saves but cannot
publish, and uploads:

<include cwd lang="ts" meta='title="tests/emails.test.ts"'>
  ../../examples/backends/next-drizzle/tests/emails.test.ts

They need Docker (Testcontainers starts a Postgres), or a database in
`TEST_DATABASE_URL`. They never read `DATABASE_URL`, which may be one you care about.
