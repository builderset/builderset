The routes, the checks and the answers are the same as in
[Next.js and Drizzle](/docs/guides/backend/next-drizzle), which explains each step;
this page shows what Prisma changes. Every file is from
[`examples/backends/next-prisma`](https://github.com/builderset/builderset/tree/development/examples/backends/next-prisma),
tested against a real Postgres on each change.

_This page describes Builderset 0.5.2._

Where the tables differ from the SQL: ids are `bigserial` rather than identity
columns, foreign keys add `on update cascade`, and Prisma keeps `updated_at` itself
(`@updatedAt`), so there is no trigger. The partial indexes need the
`partialIndexes` preview feature. `status`, `kind` and `action` stay text, as in the
SQL; their values are constants:

<include cwd lang="ts" meta='title="lib/vocabulary.ts"'>
  ../../examples/backends/next-prisma/lib/vocabulary.ts
</include>

## Publishing

`version: { increment: 1 }` counts the publish, and `Prisma.DbNull` clears the draft
to SQL `NULL`. `updateManyAndReturn` moves the design published before back to draft
and says which one it was, for its activity:
