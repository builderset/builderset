## Why it is shaped this way

- **One JSON column per version, not a table per block.** The document is checked as
  a whole and stored as a whole; nothing reads or writes inside it. A relational copy
  of the tree would be a second source that can disagree with the first.
- **`document` and `draft_document`.** Readers get `document`. Autosaves go to
  `draft_document`, so a half-written article never reaches the site, and publishing
  copies the checked draft into `document` in one statement.
- **A bigint `id` and a `uuid`.** Joins and indexes use the small integer; URLs and
  answers use the uuid, which says nothing about how many rows there are and cannot
  be guessed one after another.
- **Soft deletes with partial indexes.** A deleted row keeps its revisions, its
  activity and its responses, and can be restored. Every unique rule and every list
  index is `where deleted_at is null`, so the dead rows cost the live queries nothing
  and free the addresses they held.
- **`on delete set null` for people.** An author leaving the company must not delete
  their articles with them.
- **Revisions per builder, activity for all.** A revision belongs to one document and
  goes when it goes, so it gets a real foreign key. The activity log describes rows
  that may be gone, so it names them by type and id instead.
- **`saved_at` with milliseconds.** JavaScript's dates have milliseconds; a
  microsecond value would never compare equal to what the editor sends back.
- **Copies of the meta for lists.** An article's `title` and `excerpt`, a form's
  `slug` and `name` are written from `document.meta` in the same transaction as the
  document. Lists and search read these, and an index serves them.

## Other databases

MySQL 8 and MariaDB have a `JSON` type: use it for the documents, `datetime(3)` for
the timestamps, `binary(16)` or `char(36)` for the uuid, and an `enum` or a check for
the statuses. They have no partial indexes: put `deleted_at` into each unique index
instead — or a generated `live` column that is `1` when live and `null` when deleted,
since unique indexes ignore nulls — and keep the one-active-design rule in the
publish route. SQLite stores the JSON as text, which is fine for a small site: the
documents are always read and written whole.
