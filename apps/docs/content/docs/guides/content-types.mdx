An article is any long-form document. One project can have several kinds — blog
posts, job posts, help pages — each with its own set of elements and its own fields.
At the end you have a second kind of document, edited by the same kit.

_This page describes Builderset 0.4.0._

## Only the elements that fit

A registry decides what a writer can insert. Filter the standard elements to the
ones a job post needs:

<include cwd lang="tsx" meta='title="job-post-editor.tsx"'>
  ./snippets/guides/content-type.tsx#elements
</include>

Use the same registry on the server: a job post that somehow contains a video is
then refused by `checkArticle`, not just hidden in the menu.

## Fields of its own

A salary range, a closing date, a team: the record's own columns, edited in the
editor's Document settings beside the built-in fields. Each section is a
`settingsSections` entry; `SettingsFieldRow` gives your input the editor's label
and layout:

<include cwd lang="tsx" meta='title="job-post-editor.tsx"'>
  ./snippets/guides/content-type.tsx#fields
</include>

These values are yours: they are not part of the document. Save them with the
record, through your own API.

## Elements of its own

For something the standard elements cannot express — a salary card, a map of the
office — add a [custom element](/docs/guides/custom-elements) to this registry.
