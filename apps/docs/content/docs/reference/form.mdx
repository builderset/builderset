## The document

A form is the engine's tree with steps under the root and fields under the steps.
It adds its meta (a working name, the title, an intro, its address) and settings
(the buttons, what happens after it is sent, spam rules, limits, privacy, the look):

## Answers

`validateAnswers(form, answers)` from `@builderset/form` returns
`{ ok, errors, values }`: by field key, the first thing wrong with each answer, and
the answers to keep — shown fields only, numbers as numbers. Run it on the server
for every submission; the renderer runs the same function before each step. Why an
answer is refused:

</include>

## What visitors read

The buttons and the thank-you message are the form's own settings. The rest —
yes and no, the parts of a name, the progress line, the errors — are built in for
English, Albanian and German; pass `words` to `FormView` for another language:
